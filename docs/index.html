claude-oauth

Run Google, xAI and OpenAI models inside Claude Code, each over its own OAuth session — without replacing the native Claude path. claude stays native. claude-oauth opens the router.

Pre-release. Not ready to use, and not pretending otherwise. The open defects are listed below, by id.

Two commands, two paths

A router usually replaces something. This one adds a second entry point and leaves the first one alone. Which binary you type decides which world you are in — there is no mode to remember and nothing to switch back.

claude ──────────────▶ api.anthropic.com
Native. No proxy, no patch, no interception. Byte-for-byte the session you had before installing.
claude-oauth ──────┬───────▶ agy   → Google
      ├───────▶ grok  → xAI
      └───────▶ codex → OpenAI
Each lane drives that provider's own official CLI, under your own account and your own plan.

The boundary between those two blocks is the whole project. Everything below is about keeping it there and proving it is there.

Why a chat box is not enough

Claude Code is an agent harness, not a chat window. Its value is the loop: tools, subagents, skills, MCP servers, permission prompts, file edits that you approve. A router that only forwards text turns that harness back into a chat box with extra steps.

So the target here is the harder one. Every model reachable through the router should be able to use the same Claude Code surface — the Agent tool, skills, MCP servers such as Playwright, file editing under the same permission rules that govern a native session. Anything less is a downgrade wearing the harness's clothes.

That target is not met yet. Three of the open defects below are exactly this gap, and they are named rather than glossed.

Who this is for

  • Developers — switch models mid-workflow, run several in parallel, cross-check one against another, inside the tool you already have open.
  • Students — bring a provider's free or student tier (Google's student Gemini offer, for instance, subject to Google's own terms) into Claude Code, so the harness itself is learnable without a paid plan.

The point is to grow the harness's adoption, not to route around anyone. The native path stays untouched and stays the recommended one. Nothing here proxies, wraps or intercepts Anthropic's endpoint, and nothing here is a way to get more of anything than your own accounts already grant.

What it does not do

  • It does not touch the native path. After installation, claude talks to api.anthropic.com exactly as it did before.
  • It does not bypass anyone's authentication. Every lane launches that provider's own shipped CLI and lets it do its own OAuth, as you.
  • It does not grant entitlements. If your plan does not include a model, the router cannot conjure it. Quota exhaustion surfaces as quota exhaustion.

The one claim, and its measurement

"Installing this does not degrade native Claude Code" is a claim, so it gets a measurement instead of a paragraph. Measured on the maintainer's machine, 2026-09-07:

ArmCheckResult
Environment ANTHROPIC_BASE_URL in a normal claude session absent
Process tree ancestry of the claude process no router process
Positive claude remote-control --help in a clean environment accepted
Negative the same command with a router-style base URL refused, exit 1

The negative arm is the point. A check that cannot fail measures nothing, so the passing arms only mean something because the last row shows the instrument firing.

Scope, stated plainly: that was one machine, and the negative arm used a synthetic base URL rather than a live router window. This repository does not yet ship the launcher shim or a test that reproduces either arm, so you cannot verify the claim from the source tree alone today. Until it does, treat it as the maintainer's measurement, not as a repository-verified guarantee. Closing that gap is a release blocker, listed below as B05.

Open defects

Found by review and by independent adversarial passes. They are on the front page because a pre-release page that hides them is worth less than no page.

IdSeverityWhat is wrong
B01 critical The parent session's permission boundary is not applied to Google and xAI subagents. Write and bypass flags are set unconditionally, so executionMode: "agent-readonly" misdescribes the effective authority.
B02 high A role:"system" message that arrives after the last user message is dropped silently while compiling the request. Measured loss: ~77.5k characters — the skill catalogue, the agent catalogue, MCP instructions, the output style. No error, no warning, no detector. This is why routed models cannot see skills or Agent.
B03 medium An xAI continuation request can lose both the session identity and the new user instruction.
B04 medium The workspace write check does not write the file it checks, leaving a path race open.
B05 high The launcher shim is not in this repository, so the native-separation claim above cannot be reproduced from this tree.
B06 low The long-context announcement is also written into max_input_tokens, where the pinned snapshot is smaller.
G01 high The Google lane is not structurally connected to the Claude Code tool surface at all: MCP sessions are handed to the xAI adapter only. Even with B02 fixed, Google would not drive the harness's tool loop.
N01 high Image blocks inside a tool result are reduced to an empty string, so a Playwright screenshot returns as a successful, empty tool result.
N05 high The OpenAI capsule's own loopback port does not enforce the transport nonce, so a local process could reach it without going through the router.

Ids are the repository's own. The full list, including the ones judged lower severity and the ones already repaired, lives with the source.

How it is built

TypeScript on Node 24, no runtime dependencies in the router itself, and a check that has to stay green: lint, type-check, tests, secret scan. The tests are the part worth mentioning — not their count, but the discipline: a gate is not trusted until it has been shown to fail.

  • Negative controls. Each gate ships an arm that deliberately breaks it. A green run whose instrument has never fired is a green name, not a green measurement.
  • Diagnostics that survive. When a lane fails, the child process's own explanation is carried into the error — bounded and redacted, because a diagnostic channel must never become a leak.
  • Named causes only. An error code states a cause that was actually observed. Where the evidence is missing, the generic code stays, rather than a confident guess that sends the reader to the wrong fix.

Where this stands with Anthropic

This project exists because Claude Code is worth learning. Every hour someone spends inside the harness — even driving another provider's model through it — is an hour spent learning Anthropic's tool, its permission model and its agent loop. The native path is untouched and is the one the documentation recommends.

There is no circumvention claim here, and none is wanted: no proxying of Anthropic's endpoint, no shared or resold access, no entitlement that your own provider accounts do not already give you. If any part of this project ever reads otherwise, that part is a defect and should be reported as one.
